# CLAUDE.md

**MaelEnglish** — interactive, gamified English learning platform (slogan « Speak the Language of Your Profession »), built around its founder Ismaël Zerbo (« Coach Ish »). Next.js app, installable as a PWA. **The signed-in learner app is in English** (owner decision 2026-11-22: « don't use french words »): `(app)` pages, learner components, Lab players, badges, learner action / service messages, the word card; the shell has `lang="en"` and French content inside is marked `lang="fr"` (staff instructions, explanations, Mael's tips, objectives, module summaries — `RichText lang="fr"` —, a word's French translation / note). **Every new feature is written in English.** Still French until the owner decides: the public site, the auth pages (`/connexion`, `/activer`, password reset — and the auth service messages also shown on `/compte`), emails and WhatsApp messages, and AI feedback content meant to help in French. URLs stay French. UI labels quoted in French further down this file (« Continuer », « Mes défis »…) are now their English versions (« Continue », « My Challenges »…); **the admin / staff space is in English** (user decision 2026-11-20: `/admin/**`, admin components, the Lab editors, admin service & action messages, the staff `PreviewBar`, `lang="en"` on the admin shell; shared pieces take a label / `locale` prop — `Recorder locale="en"`, `LogoutButton label="Sign out"`; HugeRTE runs in English). Content staff write for learners (titles, objectives, instructions, questions) stays in French. Learners are mostly French-speaking professionals in West Africa, often on low-end Android phones with expensive data — keep pages light.

## Stack

Next.js 16 (App Router, `src/`), React 19, TypeScript, Tailwind CSS 4 + shadcn/ui (`components.json`, style base-nova, icons lucide), Mongoose (`src/lib/db.ts` → `connectDB()`, cached on `globalThis`, server-only). Motion (`motion/react`), dnd-kit, react-markdown + remark-gfm (older Markdown content), **HugeRTE** rich-text editor for long staff texts (see Rich text). canvas-confetti, Zustand (reward queue). Feedback sounds are synthesised with Web Audio (no audio files). Auth is custom (see below). Service worker hand-written (`public/sw.js`). Hosting: Render (`render.yaml`, Node 22) — see Deployment.

Next.js 16 differs from older versions — read `node_modules/next/dist/docs/` before using an API you're unsure about (see `AGENTS.md`).

## Data model (`src/models/`, import from `@/models`)

Mongoose 9 — **pre-hooks take no `next()`** (throw or `this.invalidate(...)` instead). Models are registered with `defineModel(name, schema)` (`src/models/define.ts`: in development it rebuilds the model on hot reload, otherwise the cached one keeps old enums — « `activity` is not a valid enum value »; production keeps the first one); types via `InferSchemaType`.

- `User` — profile (incl. **profile photo**: Media kind `avatar`, resized to a 320 px square in the browser by `components/account/avatar-picker.tsx`, linked by `setAvatar` (`src/lib/avatar.ts`, own photo or user managers; the old file is deleted), shown via `User.avatarUrl` = `/api/avatar/<id>?v=<mediaId>` (redirect to a signed URL, signed-in users) with `<Avatar>` in the navbars, `/compte` and the admin user page), roles and `passwordHash` (scrypt, `select: false`; empty until activation). Staff have a **coach name** (`coachName`, e.g. « Coach Ish », set on the admin user page): learners see `coachLabel(u)` (`src/lib/coach-name.ts`: the coach name, « Coach » added if missing, else « Coach <first name> ») on feedback, voice notes, « My Speaking Challenge » and emails; staff screens keep real names. Needs an **email OR a WhatsApp number**; `phoneE164` = `normalizePhone(phoneNumber)` (`src/lib/phone.ts`, default country 226), not unique (family phones). `username`/`email` lowercased, email unique + sparse. `ROLES`: user, english-coach, instructor, account-manager, admin, super-admin (`ADMIN_ROLES`, `STAFF_ROLES`, `hasRole`). Soft-delete: `isActive` (undefined = active, `isAccountActive`), `deactivatedAt/By`. Devices + `maxDevices` (3).
- `Course` — `program` = catalogue slug (validated against `PROGRAM_SLUGS`, `''` = none), `level`, `price` (FCFA integer, null = not set; staff information only, typed as « 30 000 » and parsed by `parsePrice`), `isPublished`, default cohort `startDate/endDate`, `instructors`, `finalExam`, `finalProject`, `isChallenge` + `challenge.themeLabel`.
- **Course structure (owner spec `~/Desktop/COURSE_STRUCTURE.md`, rebuilt from scratch 2026-11-21 — all earlier courses were deleted)**: Course (the spec's « Program »; « program » already means a catalogue slug) → Module → Unit → ordered **Steps**: a **lesson** (teaches) is followed by **at least 2 activities, no maximum** (practise it, scored; the spec said 2–3 — user decision 2026-11-22), repeated, and every unit ends with **exactly one speaking challenge** — pattern `^(L A{2,})+ C$`. Rules in `src/lib/course/validate-unit.ts` (`validateUnit`, pure; also: activities practise a lesson placed above them, lessons have content, the challenge uses a « ready » Lab activity (draft practice activities are skipped); English messages, admin only), applied to stored steps by `checkUnit` (`src/lib/course/unit-check.ts`). **Staff save freely; a unit breaking the rules is hidden from learners** (decision 2026-11-21) and the admin shows the problems live. A practice activity still a **draft** in the Lab is **skipped for learners** instead (decision 2026-11-22: work in progress mustn't hide a live unit): the rules run on the steps learners see (`learnerSteps`), drafts are listed apart (`draftNotices`, « N draft activities skipped » on the module page); a draft speaking challenge still hides the unit. Learner wording: « activités » for steps in general (counts, « Activité suivante », user decision 2026-11-21 — URLs keep `/etapes/`), « Leçon », « Activité », « Défi oral » for the kinds; the public site still says « leçons ».
- `Module` (`courseId`, `order`, `summary` = one-line objective, `description` = rich text shown folded (« À propos de ce module ») on the course map, `level` CEFR or "") → `Unit` (`courseId`, `moduleId`, `order`, `title`, `objectives[]` (French, one per line in the admin), `estimatedMinutes`; every module has at least one — `createModule` creates « Unité 1 », the last unit can't be deleted) → **`Step`** (`src/models/Step.ts`: `courseId`, `moduleId`, `unitId`, `position` 1…n without gaps (the step services renumber), `kind` lesson | activity | challenge, `title`, `estimatedMinutes`; lesson → `content` = `LessonContent` (`src/lib/course/types.ts`: rich `intro`, `videoUrl`, `audioMediaId`, `sections[]` vocabulary (term, meaning, example, audio) / grammar_rule (rule, table, examples) / dialogue (lines, audio) / tip « Le conseil de Mael »; cleaned by `cleanLessonContent`, intro sanitised with `normalizeRich`); activity → `activityId` (Lab), `lessonId` (the lesson practised), `passScore` (default 60); challenge → `activityId` (Lab `speaking_challenge`), unique per unit (partial index `one_challenge_per_unit`)). No module quiz / assignment and no final project any more (decision 2026-11-21); the course **final exam** stays. Children point to parents; no id arrays on parents.
- `Enrollment` — **the only source of course access** (one record per learner and course): unique (userId, courseId), own `startDate`/`endDate` (null = open), `status` active | suspended | completed, `suspendedReason` (`account-deactivated` = lifted on account restore). `accessState(e, now)` → active | not-started | expired | suspended | completed.
- `Activity` (`src/models/Activity.ts`) — **Labo** activity: `type` (registry `src/lib/lab/types.ts`, spec ids), title, level, tags, `status` draft | ready (a step on a draft makes its unit invalid → hidden), `content` (per type, cleaned / checked by `src/lib/lab/content.ts`).
- `StepProgress` (one per learner and lesson / activity step: `score` = best activity score, `attempts`), `QuizAttempt` (final exam only), `ChallengeSubmission` (a unit's speaking challenge: `unitId` (unique with `userId`), `stepId`, `activityId` answered, `mediaId`, `durationS`, status pending | graded | returned, grade, feedback) — all in `src/models/Progress.ts`; `TeachingResource` (staff material per module).
- `Session`, `AuthToken`, `RateLimit` (`src/models/Auth.ts`) — see Auth. All three have TTL indexes on `expiresAt`, but code always re-checks `expiresAt` (TTL deletion is lazy).
- Quiz questions (`src/models/shared.ts`): `options: [{ id, text }]` (≥ 2), `correctOptionId` must match an option.

## Auth (custom, `src/lib/auth/`)

No auth library: Better Auth needs an email per account, and many learners only have WhatsApp.
- **No self sign-up.** Staff create accounts without a password (`accounts.ts` → `createAccount`, returns an activation token); the person opens `/activer/<token>` (7 days) and chooses a password. The link is emailed when the account has an email, otherwise staff pass it on by hand. **Passwords never go through WhatsApp** (no WhatsApp activation or reset-code messages).
- **First admin**: `/installation`, open only while no admin / super-admin exists (`bootstrapAdmin`).
- **Role rules** (`assignableRoles`): admins assign user, english-coach, instructor, account-manager; account managers only user, english-coach; admin / super-admin are granted only in the database.
- **Login** (`/connexion`) by username, email or WhatsApp number (`findByIdentifier`; a number shared by several accounts asks for the username). Rate-limited in MongoDB (`hitRateLimit`: 30 / 15 min per IP, 10 per identifier).
- **Forgotten password** (`/mot-de-passe-oublie`): email link `/reinitialiser/<token>` (1 h); same answer whether or not the account exists; learners without email ask the team on WhatsApp (staff use `issueResetForUser`).
- **Sessions**: random token in the `me_session` cookie (httpOnly, lax), only its sha256 stored in `Session`; 30 days, extended daily (`validateSession`) and the cookie's lifetime is refreshed by `src/proxy.ts`. A password change / reset signs out the other sessions; deactivation (`deactivateUser`) signs out everywhere and suspends enrolments (`restoreUser` lifts only those tagged `account-deactivated`).
- **Devices**: `me_device` cookie → `User.devices` (informational, never blocks). The learner sees and revokes sessions on `/compte`.
- Layers: `service.ts` (framework-free, unit-tested in `tests/auth.test.ts`), `session.ts` (cookies; only from Server Actions), `dal.ts` (`getCurrentUser` cached per render for Server Components, `readCurrentUser` uncached for Server Actions — sharing the render cache with an action trips a Next.js dev invariant; `requireUser`, `requireRole`), `src/app/(auth)/actions.ts`. `src/proxy.ts` only does optimistic redirects for the private areas (`/compte`, `/admin`, `/mes-cours`, `/apprendre`, `/progression`); real checks are in the DAL. `getCurrentUser` calls `connection()` (session expiry depends on the clock — avoids prerender errors).
- Cache Components: anything reading cookies, params or the current time sits inside `<Suspense>` (with `await connection()` before time-dependent queries). Don't use `useSearchParams()` in auth forms: it pushes them to client-only rendering (`useNextParam` in `login-form.tsx` reads `?next=` after hydration instead); `safeNext` blocks open redirects.
- Email: `src/lib/email.ts` (nodemailer, Brevo SMTP; simulation mode without `EMAIL_*`: links are logged in development).

## Labo (`/admin/labo`, user decision 2026-11-20)

Standalone library of **reusable** practice activities (admins + instructors / coaches: `can.useLab`; adding one to a unit also needs content rights on that course). Each type has its **own editor** (`components/lab/editors.tsx`, fields named `c_<field>`) and its **own learner player**; types are **designed from scratch one by one with the owner** (the old 7-kind exercise engine was removed with the old structure). Engine (catalogue phase A, plan `~/.claude/plans/lab-exercise-catalogue.md`): common details on every activity (`src/lib/lab/meta.ts`: CEFR level, skills, theme, durationMin, French instruction, « Le conseil de Mael »; library filters); learner shell `components/lab/shell/` (`useExercise` one item per screen, `ExerciseHeader`, `FeedbackPanel`, `CheckBar` « Vérifier », `ResultsScreen` score / stars ≥50/75/90 / time / items to review / Mael's tip); shared UI `components/lab/ui/` (`AudioPlayer`, `ChoiceCards`); editor kit `components/lab/item-list-editor.tsx`; items checked in the browser, score recomputed on the server (`src/lib/lab/grade.ts`, `submitLabAttempt`); every attempt saved in `LabAttempt` + mistake bank `LabMistake` (`src/lib/lab/attempts.ts`); typed-answer matching `src/lib/lab/match.ts`; learner preview `/admin/labo/[id]/apercu`. Types so far:
- **« listen_choose »** (L1, role `practice`: an activity step): audio (upload or in-browser recording, Media kind `clip`), optional rich « mise en situation », multiple-choice questions each with an optional « moment de la réponse » (`startS`), optional transcript, `maxPlays` 0 (unlimited, practice) / 2 / 3 (exam style: each listen from the start counts, no seeking until the answers are sent, then lifted). Editor `components/lab/listening-editor.tsx` (sends `c_json` + `c_context`); player `components/lab/players/listening-player.tsx` (questions visible from the start, player pinned under the header, speeds 0.75–1.25×, 5 s back; correction: right / wrong, explanation, « Réécouter ce passage », transcript; « Recommencer » reshuffles the questions — `components/lab/shell/shuffle.ts`). Items checked in the browser, score recomputed on the server (`submitLabAttempt`); sending completes the step whatever the score, best score kept in `StepProgress.score`, retries allowed (« Recommencer » reshuffles).

## PWA, offline & accessibility

- **Installable**: `src/app/manifest.ts` (start `/mes-cours?source=pwa`, standalone, shortcuts), icons generated by `node scripts/make-icons.mjs` (vector « M » of the logo in logo blue + red bar/toggle → `public/icons/*`, `src/app/icon.png`, `apple-icon.png`; maskable variant with safe zone). `InstallPrompt` card on `/mes-cours` (Android native prompt, iOS instructions).
- **Service worker** `public/sw.js` (registered in production only by `RegisterServiceWorker`; served with no-cache headers from `next.config.ts`): static assets cache-first; navigations network-first, keeping the last copy of learner / public pages (never admin, account or auth pages); fallback `public/offline.html` (plain HTML, no Next.js scripts — a Next page would break offline when its chunks aren't cached). Bump `VERSION` when changing caching. No « download the course » button (removed, user decision 2026-11-22): only pages already opened are available offline.
- **Offline results**: `completeStep` (lesson « Continuer ») failing for lack of network are queued in localStorage (`components/pwa/offline-queue.ts`) and replayed in order by `OfflineSync` (app shell banner) when back online — the server re-checks each step. Logout (`LogoutButton`) clears the queue and cached pages (shared devices).
- **Colours / contrast**: the logo red `#ff5757` (`coral`) is used as is (user decision). **No solid red backgrounds** (user decision): buttons, cards and badges are **white with a red border** (`border-2 border-coral bg-white`, pressable red edge `shadow-[0_Npx_0_0_var(--color-coral)]`, hover `bg-coral-soft`). Red text on white has 3.1:1, so it must be large (≥ 19px bold — `BUTTON.coral` = `text-[19px] font-bold text-coral` — or ≥ 24px); small red text uses `coral-dark` `#b02a2a`. Exception: the mic button is solid `destructive` red while recording (live-mic alert). `success` `#12855a`. No `blur-3xl` blobs or header `backdrop-blur` (expensive on low-end Android): decorative glows are radial gradients. Above-the-fold photos are preloaded (`<Photo eager>`).
- Lighthouse mobile (prod build): accessibility 100 on public and learner pages; performance 88–96. Privacy policy: `/confidentialite` (owner must complete the [bracketed] legal entity, contact email and retention period).

Catalogue: `src/lib/catalog.ts` (`PROGRAMS`, `FORMAT`, `findProgram`, `formatFor`, `programPhoto`, `whatsappLink`; icons are lucide-react names). WhatsApp Cloud API client: `src/lib/whatsapp.ts` (server-only; simulation mode without token; only the enrolment template `maelenglish_inscription`).

## Conventions & history

- URLs live at the root in French (`/programmes/[slug]`, `/coaching`, `/connexion`, `/mes-cours`, `/apprendre/...`, `/admin/...`). The app replaced the MaelEnglish part of the old AfroHK Express/EJS monolith (deleted; still in git history before the « remove legacy » commit). It had no users, so there are no redirects from old URLs and the database is **new and separate** (`APP_DB`, never the AfroHK one — the server refuses to start with an AfroHK `APP_DB`).
- Public figures must be verifiable (no invented stats); founder texts in `FOUNDER` are his own words.
- Product decisions: no self sign-up (staff create accounts); no WhatsApp messages for passwords; coach validation = +20 XP; app icon = logo « M » in blue with the red bar/toggle.
- Before committing: `npm run lint`, `npm test`, `npm run build`. Tests touching the database use `mongodb-memory-server`; never point a script at a real database without checking `APP_DB`.

## Environment

See `.env.example`. Required: `APP_DB`, `APP_URL` (prod: the final https domain — baked into email links, sitemap, share images). Optional: `APP_TZ` (default Africa/Ouagadougou), `ANTHROPIC_API_KEY` (Claude: writing task correction, dictionary translations), `AZURE_SPEECH_KEY` + `AZURE_SPEECH_REGION` (Azure neural voices: dictionary pronunciation), Brevo SMTP (`EMAIL_*`; `EMAIL_FROM` must be a sender verified in Brevo — the `…@smtp-brevo.com` login is not one and Brevo silently drops such mail, so without a valid `EMAIL_FROM` email stays in simulation mode), WhatsApp Cloud API (`WHATSAPP_*`, simulation mode without token). Local: put overrides in `.env.local` (wins over `.env`). `src/instrumentation-node.ts` checks the configuration at startup (exits without `APP_DB`, warns about missing production settings).

## Deployment (Render)

`render.yaml` Blueprint: web service, Frankfurt, `npm ci && npm run build`, `npm start`, health check `GET /api/health` (200 when MongoDB answers within 3 s, else 503). Secrets (`APP_DB`, `APP_URL`, `EMAIL_*`, `WHATSAPP_*`) are `sync: false` — set them in the Render dashboard. After the first deploy: open `/installation` to create the first admin, then link the custom domain (HTTPS). Use a paid instance (the free plan sleeps).

Next: **Play Store** (Trusted Web Activity, after the final domain is live): `/.well-known/assetlinks.json`, Play developer account, store listing + data-safety form, privacy policy link, « store mode » hiding sign-up / payment buttons inside the app.
